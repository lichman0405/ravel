## Review 1 修复

### P1：偏差 provenance 不再静默丢失

`DeviationRequest` 的 `sample_id`、`raw_output_ref`、`raw_output_sha256`、`protocol_version` 只存在于 `DEVIATION_REPORTED` lab event 上，而 event 只在有 handover 时创建。原实现无 handover 时返回 201 并把四个字段丢掉，tasklog 还错误地声称两条记录都保存了它们。

修复采用“拒绝或显式链接”两者：

- 无 handover 且请求携带任一 provenance 字段：`POST .../deviations` 返回 **409**，detail 列出被拒绝的字段，说明没有 event 可存放且不会静默丢弃；deviation 和 event 都不写。
- 无 handover 且不携带 provenance：裸 observation 仍返回 201；`person_reported_event=null`、`deviation_event_link=null`、`handover_id=null`，Master 下一轮仍能读到。
- 有 handover：除 deviation 和 `DEVIATION_REPORTED` event 外，新增 append-only 的 `lab_deviation_links` 行，带 `deviation_id`、`event_id`、`handover_id`、`node_id`。唯一键 `(project_id, deviation_id)` 与 `(project_id, event_id)` 保证一对一；外键指向两张记录。响应新增 `deviation_event_link`。
- 新测试 `test_the_deviation_link_is_append_only` 验证直接 UPDATE/DELETE 该链接被 PostgreSQL 拒绝。
- 原“无 handover 偏差仍记录”测试拆成两个：携带 provenance 的 409 用例与裸 observation 的 201 用例，因此此前 tasklog 的 AC2 说法已纠正。

### P2：模拟实验不再以 `human-lab` 名称进入 HUMAN_LAB 证据

原实现中所有 lab handover 的 `backend` 都是 `human-lab`，而 T12 `classification.py` 把任何 `human-lab` execution 分类为 `HUMAN_LAB`，使 SIMULATED handover 可能被报告认证为真人实验证据（违反 `CONTRACTS.md:201`）。

修复完全在 T11 边界内完成，未修改 T12 文件：

- `REAL_BACKEND_NAME = "human-lab"`，`SIMULATED_BACKEND_NAME = "mock-human-lab"`；`BACKEND_NAME` 保留为默认的 simulated 名称。
- `HumanLabBackend.name` 是 `field(init=False)`，在 `__post_init__` 中由 `live_lab` 派生；构造器不再接受名称参数，调用者无法把模拟部署命名为 `human-lab`。
- `live_lab=True` 但无覆盖 binding 的负责人确认时，`submit` 抛 `LabConfigurationError`，不再回退为 SIMULATED；因此不会出现“真名下的模拟证明”。原“无确认则 SIMULATED”的测试已改为断言拒绝且不留下 handover 行。
- `reference_for` 使用 handover 冻结的 `backend`，权限变化后旧引用仍可解析；`parse_ref` 接受 `human-lab:` 与 `mock-human-lab:` 两种前缀。
- 新增 `tests/premium/T11/test_execution_typing.py`：一个测试验证名称由模式派生；一个测试把 SIMULATED execution 写入 ledger 并组装报告，断言 `data_mode=SIMULATED` 且 evidence type 为 `SIMULATED`（不是 `HUMAN_LAB`）；另一个测试用 REAL handover 断言 `data_mode=REAL` 且 evidence type 为 `HUMAN_LAB`。报告 data mode 是项目级派生，因此两个场景各用一个独立项目，避免同一项目中的另一条 execution 把模式变成 MIXED。

### P3：防御性修复与记录的缺口

已修复：

- `LabEventRepository.record_milestone` 先调用 `_authorize(event)`，不再绕过项目作用域检查。
- `lab_upload_receipts` 新增结构化 `sample_id` 与 `declared_protocol_version`（含正整数 check），不再只把声明放在自由文本 `detail`。`protocol_version` 仍是 handover 必须回答的版本；错误声明作为差异保留，不覆盖真值。所有五种 receipt 路径都写入这两个字段。

记录但未修复：

- **同一 output 的并发首次上传可能重复。** `record_upload` 先查 `(node_id, name, provenance)` 是否已有 artifact；`artifacts` 没有该组合的唯一约束，`lab_events` 也没有 `OUTPUT_UPLOADED` 的 `(handover_id, raw_output_ref, raw_output_sha256)` 唯一约束。两个并发首次上传都可能看到“不存在”，从而各自创建 artifact/version/event。正确修复需要在共享 artifact 表上加唯一约束，并让路由把约束冲突转换为幂等重试或明确的 409；这超出 T11 局部范围，且会影响 artifact 通用写入路径，因此留作已知缺口，而不是在没有并发测试的情况下临时加约束。

## 实现摘要

1. **HumanLabBackend 的人员报告链**（`src/ravel/backends/lab/backend.py`）
   - `live_lab` 默认 false；只有 `live_lab=True` 且有覆盖该包的负责人确认时，handover 才以 `REAL` 打开。
   - handover 持久化 `execution_mode` 与 `lead_confirmation_ref`，此后不可改写；状态、交付和采集结果都同时返回 `execution_mode`、`evidence_execution_type` 和 `person_reported_events`。
   - 等待实验人员期间，handover 始终是 `WAITING_EXTERNAL`；签收和开始报告都只是人员事件，不产生 `RUNNING`。`instrument_state` 与 `scientific_verdict` 在所有实验面显式为 `null`。
   - 系统 `cancel()` 只把 handover 置为 `CANCELLED`、撤销交接与接收资格，并在 detail/视图中显示等待人工停止确认；不写 `STOP_CONFIRMED`，不声称仪器已停止。人员随后确认停止只清除等待标志，不改变 `CANCELLED`。
   - 删除了会从 artifact 创建元数据合成 `person_reported=True` 事件的旧 helper；人员报告只能由人员经过 Gateway 产生。

2. **实验包绑定与负责人确认**（`src/ravel/state/repositories/lab.py`、`src/ravel/domain/lab.py`）
   - `LabPackageRepository.ensure_bound` 从 preparation manifest/contract 派生 `LabPackageBinding`：protocol version、样品 ID（materializer 的 `S-1..S-n`）、必交原始文件、设备标识、SOP 引用。读取不会创建 binding。
   - `LabLeadConfirmation.covers(binding)` 只在 protocol version、设备、SOP 成员关系和场地都相符时覆盖；`ready_for_real_execution` 是派生值，没有可变 ready 标志。
   - 负责人确认只允许 `PROJECT_OWNER`；人员事件只允许 `LAB_USER`；跨项目经 `PrincipalDep` 返回 404，不泄露项目存在性。

3. **Gateway 人员流程**（`src/ravel/gateway/routes/lab.py`）
   - `POST .../sign-off`：记录 `ACKNOWLEDGED`，幂等，要求 handover 处于等待中，可校验 contract version。
   - `POST .../start`：要求已有签收；记录 `START_REPORTED`，幂等，不移动 handover 状态。
   - `POST .../stop-confirmation`：记录 `STOP_CONFIRMED`，可在系统取消后使用；不改变 handover 状态。
   - `POST .../lead-confirmation`：`PROJECT_OWNER` 确认 SOP/场地/设备；校验 preparation、node、version、device 和 SOP，写一次且只写一次。
   - `POST .../uploads`：只接受命名输出；按 SHA-256 与大小保存 artifact，写 `OUTPUT_UPLOADED` 人员事件和 `LabUploadReceipt`。未要求输出、错误 contract version、错误 sample、迟到上传都保留拒绝 receipt 与结构化的 sample/declared version；文件本身不落 artifact。声明的旧版本上传保留来源与 hash，但不能回答新版本 handover，也不能完成 run。
   - `POST .../deviations`：保留偏差原文、操作者（LAB_USER）、时间、sample_id、原始文件引用和 SHA-256；有 handover 时同时写 deviation、event 和显式 link；无 handover 时按 P1 规则拒绝 provenance，或记录裸 observation。仍走既有 deviation→Master 回路。
   - 所有实验视图都带 `real_lab_acceptance = {status: BLOCKED_EXTERNAL, task: T26, ...}`，上传/偏差响应明确 `scientific_verdict: null`。

4. **证据类型与模拟边界**（`src/ravel/domain/enums.py`、`src/ravel/domain/lab.py`）
