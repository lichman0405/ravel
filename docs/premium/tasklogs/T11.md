## 实现摘要

1. **HumanLabBackend 的人员报告链**（`src/ravel/backends/lab/backend.py`）
   - 新增 `live_lab: bool = False`。只有同时满足 `live_lab` 与覆盖该包的实验负责人确认，handover 才以 `REAL` 打开；默认自动流程是 `SIMULATED`。
   - handover 持久化 `execution_mode` 与 `lead_confirmation_ref`，此后不可改写；状态、交付和采集结果都同时返回 `execution_mode`、`evidence_execution_type` 和 `person_reported_events`。
   - 等待实验人员期间，handover 始终是 `WAITING_EXTERNAL`；签收和开始报告都只是人员事件，不产生 `RUNNING`。`instrument_state` 与 `scientific_verdict` 在所有实验面显式为 `null`。
   - 系统 `cancel()` 只把 handover 置为 `CANCELLED`、撤销交接与接收资格，并在 detail/视图中显示等待人工停止确认；不写 `STOP_CONFIRMED`，不声称仪器已停止。人员随后确认停止只清除等待标志，不改变 `CANCELLED`。
   - 删除了会从 artifact 创建元数据合成 `person_reported=True` 事件的旧 helper；人员报告只能由人员经过 Gateway 产生。

2. **实验包绑定与负责人确认**（`src/ravel/state/repositories/lab.py`、`src/ravel/domain/lab.py`）
   - `LabPackageRepository.ensure_bound` 从 preparation manifest/contract 派生 `LabPackageBinding`：protocol version、样品 ID（materializer 的 `S-1..S-n`）、必交原始文件、设备标识、SOP 引用。读取不会创建 binding。
   - `LabLeadConfirmation.covers(binding)` 只在 protocol version、设备、SOP 成员关系和场地都相符时覆盖；`ready_for_real_execution` 是派生值，没有可变 ready 标志。
   - 负责人确认只允许 `PROJECT_OWNER`；人员事件只允许 `LAB_USER`；跨项目经 `PrincipalDep` 返回 404，不泄露项目存在性。

3. **Gateway 人员流程**（`src/ravel/gateway/routes/lab.py`）
   - `POST /projects/{project_id}/lab/tasks/{task_id}/sign-off`：记录 `ACKNOWLEDGED`，幂等，要求 handover 处于等待中，可校验 contract version。
   - `POST .../start`：要求已有签收；记录 `START_REPORTED`，幂等，不移动 handover 状态。
   - `POST .../stop-confirmation`：记录 `STOP_CONFIRMED`，可在系统取消后使用；不改变 handover 状态。
   - `POST .../lead-confirmation`：`PROJECT_OWNER` 确认 SOP/场地/设备；校验 preparation、node、version、device 和 SOP，写一次且只写一次。
   - `POST .../uploads`：只接受命名输出；按 SHA-256 与大小保存 artifact，写 `OUTPUT_UPLOADED` 人员事件和 `LabUploadReceipt`。未要求输出、错误 contract version、错误 sample、迟到上传都保留拒绝 receipt；文件本身不落 artifact。声明的旧版本上传保留来源与 hash，但不能回答新版本 handover，也不能完成 run。
   - `POST .../deviations`：保留偏差原文、操作者（LAB_USER）、时间、sample_id、原始文件引用和 SHA-256；仍走既有 deviation→Master 回路。没有 handover 时 deviation 照常记录，但响应明确没有可挂的人员实验事件，不伪造事件。
   - 所有实验视图都带 `real_lab_acceptance = {status: BLOCKED_EXTERNAL, task: T26, ...}`，上传/偏差响应明确 `scientific_verdict: null`。

4. **证据类型与模拟边界**（`src/ravel/domain/enums.py`、`src/ravel/domain/lab.py`）
   - 新增 `LabExecutionMode`、`LabEventType`、`LabUploadOutcome`。
   - 自动模拟人员的上传保留既有 provenance `lab-upload:<handover_id>` 以兼容原交接链，但 artifact `kind` 标记为 `simulated`；只有带人员 `OUTPUT_UPLOADED` 事件的模拟 artifact 才能回答 `SIMULATED` handover，`REAL` handover 永不接受模拟 artifact。T12 的 SIMULATED/HUMAN_LAB 分类因此保持可区分。

5. **数据库约束与迁移**（`src/ravel/state/tables.py`、`guards.py`、`migrations/versions/20261020_1800_b8d3f2a6c9e1_human_lab_events.py`）

   - 新表 `lab_package_bindings`、`lab_lead_confirmations`、`lab_events`、`lab_upload_receipts` 全部 append-only；`guards.install` 拒绝对它们的 UPDATE/DELETE。
   - `lab_handovers.execution_mode` / `lead_confirmation_ref` 加入 identity columns，UPDATE 被拒；`execution_mode` 有 `SIMULATED|REAL` check。
   - `lab_events.person_reported` 由 `CHECK (person_reported)` 强制为真；`raw_output_sha256` 有 64 位小写十六进制 check；`deviation_note` 最长 4000；`ACKNOWLEDGED`/`START_REPORTED`/`STOP_CONFIRMED` 每 handover 各由 partial unique index 限一次，偏差和上传可重复。
