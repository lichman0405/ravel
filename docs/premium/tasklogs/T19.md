## 实现

1. **独立 sandbox-supervisor（唯一 Docker socket 持有者）**：
   `src/ravel/sandbox/service.py`、`supervisor.py` 提供 HTTP API；`docker_engine.py` 是唯一
   调用 Docker CLI 的模块（argv 列表、无 shell、超时与输出脱敏）。API/DSH/Agent 侧只有
   `provider.py` 的 HTTP 客户端，不 import Docker SDK/CLI。`infra/sandbox/docker-compose.sandbox.yml`
   只允许 `sandbox-supervisor` 服务挂载 `/var/run/docker.sock`，并只发布
   `127.0.0.1:${RAVEL_SANDBOX_SUPERVISOR_PORT:-8799}`；root compose 不含 socket。测试
   `test_application_container_has_no_docker_socket_and_uses_the_supervisor` 用 canonical
   应用镜像实际启动一个无 socket、只读 rootfs、非 root 的容器，在其中通过 HTTP 驱动真实
   sandbox，并证明容器内 `docker version` 无法连接 daemon。
2. **每 Project 一个非特权命令容器**：默认 2 CPU、4 GiB RAM（Memory=MemorySwap）、
   256 PID、10 GiB `/tmp` tmpfs（noexec/nosuid/nodev）、120 秒 wall clock；只读 rootfs、
   UID/GID 65534、`--cap-drop ALL`、`no-new-privileges`、Docker 默认 seccomp（不传
   `seccomp=default`，因为 Docker 29.1.3 会把它当 profile 路径）、无 privileged、无
   host PID/IPC/network。唯一挂载是该 Project 的命名 volume（`ravel-t19-ws-<digest>`）到
   `/workspace`，不存在 host bind。生产上限在 `src/ravel/config.py`
   （`sandbox_max_cpu_cores`、`sandbox_max_memory_bytes`、`sandbox_max_pids`、
   `sandbox_max_scratch_bytes`、`sandbox_max_timeout_seconds`），
   `sandbox/authority.py` 同时应用角色白名单和 `AuthorityEnvelope`，取二者更严格值；
   请求超过部署上限被拒绝而不是静默缩小。
3. **网络**：命令容器 `--network none`。浏览器 sandbox 每 Project 一个 `--internal`
   Docker network，仅两个 peer：浏览器容器与 egress proxy；proxy 另外接入 egress fixture
   network，按精确 `host:port` allowlist + 公网地址策略转发，拒绝 RFC1918、loopback、
   link-local、NAT64 内嵌 loopback 和 metadata（169.254.169.254 等）。重定向与子资源在
   Chromium route 内再次检查；proxy 以实际 socket 为准，并校验客户端 CIDR。浏览器容器
   只有只读 workspace volume，无 socket；proxy 容器只读、非 root、cap-drop ALL。
4. **路径与 artifact**：路径先做词法校验（拒绝 `..`、绝对路径），容器内逐段 `lstat`，
   最终 `O_NOFOLLOW` 打开；symlink 与硬链接（nlink>1）被拒绝。artifact 只能经
   `collect`（supervisor 读取字节并计算 sha256）→ RAVEL Gateway / `ArtifactRepository`
   （重新计算 hash、注册 `ArtifactStore`）；测试用内存 `MemoryArtifactStore`（未使用
   MinIO），但 PostgreSQL、repository、hash 校验全部真实。sandbox 没有 PG/cluster 凭据，
   不能写权威 State 或实验记录。
5. **Research 接线**：`src/ravel/research/browser.py` 的 Playwright 路径改为
   `DockerSandboxProvider.fetch`：应用进程不 import/启动 Playwright；要求
   `RAVEL_RESEARCH_BROWSER_SANDBOX_PROVIDER=docker`、supervisor URL/token、可信
   `RAVEL_PROJECT_ID` 与 `RAVEL_ROLE=RESEARCH`（可选 binding/epoch）。`BOUND_SANDBOX_PROVIDERS`
   保持为空（T07 fail-closed 静态断言不变），`IMPLEMENTED_SANDBOX_PROVIDERS={"docker"}`；
   `DockerSandboxProvider.fetch` 在浏览器容器内渲染并返回 DOM。真实 `ResearchSourceGateway`
   注册 rendered snapshot，`ArtifactRepository.verify` 与 source `content_hash` 相等。
   无 GUI computer control，只有导航/读取。
6. **生命周期与记录**：stop 停容器并保留 handle/workspace/run 记录；reconnect 复用同一
   project binding/epoch 重启；destroy 删除容器与 volume，但 handle/run 记录仍可查询；
   supervisor 重启把在途 run 标为 `LOST`。资源与日志归 supervisor 所有，agent 只拿到
   脱敏的 `GET /handles/{id}/logs`。命令 argv/输出/记录/日志按下述规则脱敏：精确 secret、
   assignment、Bearer、URL userinfo、flag、query 模式，全部替换为 `[REDACTED]`。

## 已知边界

- **supervisor token 是全部署共享能力**：一个 token 持有者若同时知道其他 Project id，
  可以为该 Project provision sandbox；handle 的 project 检查已阻止跨 Project 使用，
  但 per-project token/mTLS 尚未实现（V0）。
- **seccomp**：使用 Docker 默认 profile，而非 RAVEL 自定义 allowlist；默认 profile 是真实
  限制（容器内核状态可见 `Seccomp=2`），但策略归发行版所有。
- **Chromium `--no-sandbox`**：非 root、只读 rootfs、no-new-privileges 下 Chromium 自带
  setuid sandbox 无法初始化；Docker 容器是边界，浏览器进程无额外 Chromium sandbox。
- **单一 Docker daemon 是信任域**：能到达 supervisor 的 Project 可以按其配额消耗宿主
  CPU/磁盘；supervisor 只做每 Project/用途一个 sandbox，没有全局 sandbox 数量上限。
- **浏览器 workspace 只读**；浏览器无直接 egress，只能经 proxy；无 GUI computer control。
- **停止宽限**：测试配置 `RAVEL_SANDBOX_STOP_GRACE_SECONDS=2`；生产可配置。
- **live 公网研究不在 T19**：T19 验证 sandbox 隔离与真实本地浏览器渲染；真实公网站点
  抓取由后续 external Research 行认证。fixture 来源在相关路径中标注为 fixture，
  不作为公网证据。
- **全量 unit 的 2 个既有失败**：base 已存在，T19 范围外，未修复（避免越界修改）。
