## 架构与边界

- 桌面是 thin local client：不持有 Project State，不写 Scientific DAG，不绕过 Gateway 的认证与角色检查。
- 登录使用 T13 生成的 `@ravel/api-client` V1 方法（`login_v1_auth_login_post`、`refresh_v1_auth_refresh_post`、`logout_v1_auth_logout_post`、`list_projects_v1_projects_get`）；没有手写重复 API 类型，也不存在 DAG mutation 方法。
- 主进程保存 token；渲染进程只通过 preload 的显式白名单 IPC 访问会话投影。渲染进程没有 token、`fetch`、localStorage/sessionStorage，也没有 Node/Electron 远程模块。
- token 优先写入 Electron `safeStorage`（Windows 上为 DPAPI）加密信封；不可用时只留内存，绝不写明文。登出删除信封。
- 浏览器窗口安全设置：`contextIsolation=true`、`nodeIntegration=false`、`sandbox=true`、`webSecurity=true`、`webviewTag=false`；禁止新窗口、外部导航、权限请求与非配置 origin；CSP `connect-src 'none'`。
- Compute/Lab 的 V0 mock 不在此任务的 UI 中展示；Windows 证据中的项目来自真实 Gateway + 真实 PostgreSQL。

### T14-AC2 — 恶意 renderer/导航/IPC 不能执行 shell、读取 .env 或转发 token

结果：PASS（Windows 真实 Electron；Linux 静态与可执行审计）。

- 渲染进程 localStorage/sessionStorage 为空，DOM 中无 JWT 形状值；桥面没有 shell/exec/spawn/file/env/token/invoke 类名字。
- 打包后的 renderer 同样验证了 Node 全局为 undefined、桥面为同一白名单（`packaged.renderer_security`）。

## 实现过程中的失败与修复

1. `run_node_suite.sh` 在容器内执行 `git archive` 报 `detected dubious ownership`：在单次命令上加 `-c safe.directory="$repo_root"`，不写全局配置（提交 `f7fa3b3`）。
2. 容器内 `git status` 因 host `core.autocrlf=true` 与容器默认不同而把大量文件报为修改：在 `t14-build` 运行时设置 `core.autocrlf=true` 与单目录 `safe.directory`，这是容器环境修复，未修改仓库文件。
3. ruff 首轮报 I001、F401（未使用 `socket`）、F811（fixture 重名导入）：删除未用导入、排序导入、重命名参数并加必要的 `# noqa: F811`；最终 `make lint` 0 errors/0 warnings。
4. 早期 Electron 驱动在窗口尚未可见时调用 `isVisible()`：增加最长 60 秒的 `waitForWindowVisible` 轮询。
5. 失败路径未 await `page.screenshot` 造成二次 rejection：改为带超时的 await。
6. `refreshFingerprint` 在 `app.evaluate` 中 `require("node:fs")` 不可用：改为把 ciphertext 传入主进程，用全局 `crypto.subtle` 计算指纹。
7. portable wrapper 与 Playwright 主进程检查协议不兼容：改为启动真实进程、验证真实窗口，再通过打包应用自身的 DevTools 端点驱动 renderer；桌面截图改用 `SetProcessDPIAware` + `ShowWindow`/`SetWindowPos` + `PrintWindow(PW_RENDERFULLCONTENT)`，解决了截图只含标题栏/其它窗口的问题。
